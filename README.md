# Alem Practice — Django MVP

Платформа по кейсу HackAlem: бизнес уточняет задачу, подтверждает карточку и публикует её. Команды предлагают решения, бизнес вручную выбирает исполнителей и подтверждает этапы.

## Запуск

Python 3.10+, Django 5.2.17, SQLite. Windows:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_demo
.\.venv\Scripts\python.exe manage.py runserver
```

Открыть http://127.0.0.1:8000/. Linux/macOS: используйте `.venv/bin/python`.

Настройки автоматически загружаются из `.env` в корне проекта. При новом клонировании скопируйте `.env.example` в `.env` и замените `DJANGO_SECRET_KEY` случайным секретом. Системные переменные окружения имеют приоритет над файлом. `.env` исключён из Git; `.env.example` содержит только шаблон. `OPENAI_API_KEY` и `OPENAI_MODEL` используются для запросов OpenAI на сервере. Если модель не указана, используется gpt-5.4-mini.

Демо: `business` — бизнес, `team1`…`team5` — команды. Пароль: `AlemDemo2026!`. Seed создаёт пять синтетических карточек с исходными описаниями, пять команд и пять откликов; повторный запуск сохраняет существующие записи и пароли. Ссылки example.com демонстрационные, реальных прототипов там нет.

## Архитектура

`config/` — настройки и маршрутизация; `projects/models.py` — задачи, команды, предложения; `services.py` — рейтинг и помощник; `views.py` — сценарии и права доступа. `templates/` и `static/` — Django-шаблоны и CSS без сборки фронтенда. Авторизация, сессии и CSRF — стандартные Django. Регистрация в MVP не предусмотрена. Для управления данными: `manage.py createsuperuser`, затем `/admin/`.

## Рейтинг

Контекст + потребность: 20; данные: 20; результат: 15; критерии успеха: 15; ограничения: 10; пользователи: 10; контакт + взаимодействие: 10. Группа получает полный вес, если все её поля непустые и карточка подтверждена. Пробелы не учитываются. Это оценка полноты, а не истинности текста.

0–39 — черновик; 40–69 — рабочая; 70–89 — готовая; 90–100 — приоритетная. Пересчёт при каждом подтверждённом редактировании. Публикация отдельная и ручная. Все опубликованные задачи доступны для откликов независимо от рейтинга. Сортировка по рейтингу, затем дате изменения; поиск и фильтры по теме и готовности.

Количество предложений и выбранных команд не ограничено. Предложения видны владельцу задачи и соответствующей команде. За выбор баллы не начисляются. Выбранная команда передаёт результат этапа, бизнес подтверждает его: +25 баллов один раз за отклик. Повторное подтверждение не увеличивает баллы. Подтверждённый этап нельзя отклонить. Один этап на отклик — упрощение MVP.

## OpenAI

Конструктор работает по шагам. Пользователь заполняет текущий блок и нажимает «Далее»: сервер анализирует введённый текст через Responses API со Structured Outputs и возвращает 0–3 вопроса только по текущему блоку. Границы смысла каждого блока описаны в projects/question_scopes.py; отдельный запрос проверяет принадлежность и редакторский стиль уточнений до показа. Подсказки формулируются как «Добавьте…», «Уточните…», «Опишите…» и предлагают дополнить единое описание, а не подтвердить уже сказанное. При отсутствии API локальные подсказки показываются только для пустых полей. Если подходящих вопросов нет, можно продолжить без уточнений. Это модельная проверка, а не абсолютная гарантия. Вопросы показываются под полями до перехода дальше. Пользователь дополняет текст и нажимает «Продолжить» либо «Проверить уточнения» для повторного анализа. Пустые необязательные поля допускаются; если ответа пока нет, можно продолжить после вопросов.

Назад можно вернуться с сохранением введённого текста. Данные и вопросы хранятся в серверной сессии, обновление страницы не повторяет платный запрос. Изменения попадают в карточку и рейтинг только после итоговой проверки и подтверждения. Выход из аккаунта завершает сессию, поэтому незавершённые изменения нужно подтвердить перед выходом. В MVP параллельное редактирование одной задачи в нескольких вкладках не поддерживается; устаревшие шаги отклоняются.

Настройки: `OPENAI_API_KEY` и `OPENAI_MODEL` из .env. Реализация в `projects/ai.py`, промпт в `projects/services.py`. Контактное поле заменяется признаком наличия контакта; остальные текстовые поля отправляются как введены. Запросы используют `store=False`, таймаут 30 секунд, без автоматических повторов, максимум 2000 выходных токенов и 24 000 символов входа. Ответ проверяется по схеме и длине вопросов. Модель может ошибаться: содержание проверяет человек.

При отсутствии ключа, ошибке доступа, квоте, сетевой ошибке, отказе или некорректном ответе показываются локальные вопросы с явным сообщением. Ключи и тексты карточек не записываются в журналы интеграции. Проверка блока использует до двух платных API-запросов (генерация и проверка смысла), каждый с таймаутом 30 секунд; для публичного развёртывания добавьте ограничение частоты на пользователя.

## Проверки

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py test
```

Тесты проверяют полный сценарий, рейтинг, права доступа, публикацию только после подтверждения, отклик при нулевом рейтинге, некорректные ответы помощника и отсутствие повторных баллов.

## Демонстрация за 5 минут

1. Под business создать задачу «Теряем заявки» с коротким описанием.
2. Посмотреть вопросы, подтвердить неполную карточку и увидеть низкий рейтинг.
3. Дополнить поля, подтвердить, увидеть рост до 100, опубликовать.
4. Под team1 найти задачу и отправить идею, план и срок.
5. Под business выбрать команду; под team1 передать результат; под business подтвердить этап. В кабинете команды появятся 25 баллов.

## Ограничения

Локальный демонстрационный MVP. Не запускайте seed_demo на публичном сервере: пароли общедоступны. DEBUG включён по умолчанию. Для развёртывания задайте `DJANGO_DEBUG=0`, `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`, настройте HTTPS, защищённые cookies, статические файлы и производственный сервер. Регистрация, аудит, приватность контактов — последующие этапы.
